# Подключение Telegram

TelegramModule отправляет украинские сводки завершённых 15-минутных окон. После настройки включи TELEGRAM_ENABLED=true в .env и выполни docker compose up -d api. Токен и chat ID обязательны только при включении.

1. В Telegram открой официального [@BotFather](https://t.me/BotFather), отправь `/newbot`, выбери имя и username. Сохрани выданный токен в серверном `/root/aircontrol/backend/.env` как `TELEGRAM_BOT_TOKEN`. Это другой секрет, не DEVICE_TOKEN. В Git/чат его не отправляй.
2. Открой созданного бота и нажми **Start**, либо отправь `/start`. Бот должен получить сообщение от тебя, чтобы мы определили chat ID.
3. На сервере из `/root/aircontrol/backend` выполни:

```sh
docker compose run --rm --no-deps api npm run telegram:chat
```

Команда читает свежую .env через Compose и выводит ID, тип и название/username чатов. Выбери свой личный чат, запиши его ID в `.env` как `TELEGRAM_CHAT_ID`. Если список пуст, отправь боту новое сообщение и повтори. Для нового бота webhook не нужен; у уже используемого бота getUpdates может конфликтовать с webhook/другим polling-процессом — не отключай их вслепую.

4. Отправь одно тестовое сообщение:

```sh
docker compose run --rm --no-deps api npm run telegram:test
```

Успех — сообщение «Aircontrol: подключение к Telegram работает…» в выбранном чате. Команда отправляет одно тестовое сообщение; сводки запускаются отдельно через TELEGRAM_ENABLED=true.

Следующие расширения: сводка за день, длительное превышение и восстановление. Моковые показания должны явно оставаться тестовыми. Сводки уже обрабатываются отдельным worker со статусами в БД; сбой Telegram не блокирует сохранение измерений.

Источники: [официальный tutorial](https://core.telegram.org/bots/tutorial), [getUpdates](https://core.telegram.org/bots/api#getupdates), [sendMessage](https://core.telegram.org/bots/api#sendmessage).

## Канал

Добавь бота администратором канала с правом публикации сообщений. Отправь новый пост после добавления и выполни telegram:chat: выбери запись type=channel. Сохрани числовой ID (обычно отрицательный) в TELEGRAM_CHAT_ID. Не выбирай ID личного диалога, если цель — канал. При получении обновлений helper также показывает title/username для различения чатов. Токен не выводится.

## Сводки

Раз в 15 секунд worker проверяет последнее завершённое окно :00–:15, :15–:30 и т. д. Даём 60 секунд на приход данных. На старте обрабатывается только последнее завершённое окно, старые интервалы после простоя не рассылаются пачкой. Время отображается в Europe/Kyiv. Местоположение: Кривий Ріг · Центрально-Міський район, Гданцівка. Средние по measured_at, только для настроенного DEVICE_ID; mock и pms5003 показываются отдельными блоками. Нет данных — сообщение об отсутствии измерений. Записи с null-временем не подменяются received_at в средних. Поздние данные после подготовки сообщения не меняют уже подготовленный текст.

360 фактов на украинском находятся в src/modules/telegram/data/air-facts.uk.json. У каждого ID и sourceUrl (EPA, NOAA/NWS, NASA, USGS, Met Office), ссылка включена в сообщение. Выбор случайный, последние 10 выбранных фактов исключены. Полный цикл из 360 дней без повторов пока не реализован; текущая рассылка остаётся раз в 15 минут. Это общие факты, не объяснение причин текущих значений и не прогноз погоды. Дата редакционной проверки источников: 2026-09-08. Свежих метеоданных и AI-генерации нет.

Структура: MeasurementsService.findForPeriod получает entity за [start, end); calculateAverages в measurements/utils считает среднее каждого PM-поля отдельно для каждого source. TelegramService собирает эти шаги, summary.ts формирует текст, TelegramClient отправляет HTTP-запрос. Для небольшого потока одного устройства загружаем измерения в память; при росте количества устройств/длительности окна стоит вернуть SQL AVG.

TelegramDeliveriesService через Repository работает с существующей таблицей telegram_deliveries. Перед отправкой вставляется запись sending; уникальность device/chat/window не позволяет повторно занять период. После успеха записываются sent и message_id. При ошибке — unknown, без автоматических повторов (включая 429). Если процесс оборвался, запись может остаться sending; такой период также не повторяется. При sending/unknown проверяй канал вручную. Старые pending/failed записи сохраняются и автоматически не возобновляются. Поля attempts/next_attempt_at старой схемы сохранены для совместимости; очереди повторов и advisory lock больше нет. Это одна попытка отправки на период, возможен пропуск; exactly-once не обещаем. Ошибки логируются без токена.


Рассылка работает независимо от сохранения измерений. Для остановки задай TELEGRAM_ENABLED=false и выполни docker compose up -d api.
