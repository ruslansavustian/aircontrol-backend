# Подключение Telegram

TelegramModule отправляет украинские сводки завершённых 15-минутных окон. После настройки включи TELEGRAM_ENABLED=true в .env и выполни docker compose up -d api. Токен и chat ID обязательны только при включении.

1. В Telegram открой официального [@BotFather](https://t.me/BotFather), отправь `/newbot`, выбери имя и username. Сохрани выданный токен в серверном `/root/aircontrol/backend/.env` как `TELEGRAM_BOT_TOKEN`. Это другой секрет, не DEVICE_TOKEN. В Git/чат его не отправляй.
2. Открой созданного бота и нажми **Start**, либо отправь `/start`. Бот должен получить сообщение от тебя, чтобы мы определили chat ID.
3. На сервере из `/root/aircontrol/backend` выполни:

```sh
docker compose run --rm --no-deps api npm run telegram:chat
```

Команда читает свежую .env через Compose и выводит только ID и тип чатов. Выбери свой личный чат, запиши его ID в `.env` как `TELEGRAM_CHAT_ID`. Если список пуст, отправь боту новое сообщение и повтори. Для нового бота webhook не нужен; у уже используемого бота getUpdates может конфликтовать с webhook/другим polling-процессом — не отключай их вслепую.

4. Отправь одно тестовое сообщение:

```sh
docker compose run --rm --no-deps api npm run telegram:test
```

Успех — сообщение «Aircontrol: подключение к Telegram работает…» в выбранном чате. Команда именно отправляет сообщение; автоматически при запуске API ничего не отправляется.

Следующие расширения: сводка за день, длительное превышение и восстановление. Моковые показания должны явно оставаться тестовыми. Для надёжной доставки добавим отдельный обработчик/очередь, чтобы сбой Telegram не мешал записи измерений в PostgreSQL.

Источники: [официальный tutorial](https://core.telegram.org/bots/tutorial), [getUpdates](https://core.telegram.org/bots/api#getupdates), [sendMessage](https://core.telegram.org/bots/api#sendmessage).

## Канал

Добавь бота администратором канала с правом публикации сообщений. Отправь новый пост после добавления и выполни telegram:chat: выбери запись type=channel. Сохрани числовой ID (обычно отрицательный) в TELEGRAM_CHAT_ID. Не выбирай ID личного диалога, если цель — канал. При получении обновлений helper также показывает title/username для различения чатов. Токен не выводится.

## Сводки

Раз в 15 секунд worker проверяет последнее завершённое окно :00–:15, :15–:30 и т. д. Даём 60 секунд на приход данных. На старте обрабатывается только последнее завершённое окно, старые интервалы после простоя не рассылаются пачкой. Время отображается в Europe/Kyiv. Местоположение: Кривий Ріг · Центрально-Міський район, Гданцівка. Средние по measured_at, только для настроенного DEVICE_ID; mock и pms5003 показываются отдельными блоками. Нет данных — сообщение об отсутствии измерений. Записи с null-временем не подменяются received_at в средних. Поздние данные после подготовки сообщения не меняют уже подготовленный текст.

100 фактов на украинском находятся в src/modules/telegram/data/air-facts.uk.json. У каждого ID и sourceUrl (EPA/NOAA), ссылка включена в сообщение. Выбор случайный, последние 10 выбранных фактов исключены. Это общие факты, не объяснение причин текущих значений и не прогноз погоды. Дата редакционной проверки источников: 2026-09-08. Свежих метеоданных и AI-генерации нет.

Таблица telegram_deliveries хранит текст, факт, окно, попытки, статус и Telegram message_id. Уникальность device/chat/window плюс advisory lock PostgreSQL предотвращают обычные повторы и конкуренцию worker. При 429 учитывается retry_after, максимум 5 попыток до устаревания окна. Ошибки доступа не повторяются автоматически. После неоднозначной сетевой ошибки или падения в момент отправки статус unknown, автоматического повтора нет: это предотвращает возможный дубль ценой возможного пропуска. Telegram sendMessage не даёт гарантии exactly-once. При unknown проверяй канал вручную. Ошибки логируются без токена; успешные сообщения не засоряют лог.

Рассылка работает независимо от сохранения измерений. Для остановки задай TELEGRAM_ENABLED=false и выполни docker compose up -d api.
